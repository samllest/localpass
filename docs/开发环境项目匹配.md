# 开发环境项目匹配（1.3.0）

LocalPass 在 localhost、回环地址、内网 IP 和 `.localhost` / `.local` / `.test` 网站中，先按主机和端口，再按项目名称匹配密码。不同端口继续独立；同端口下名称不同的项目分别保存。

扩展优先使用网页的 `og:site_name` 或 `application-name`，缺失时使用登录页的标签标题。登录后的标题变化不会改变本次登录提交时的项目名称。仅统一名称中的空白、全半角字符和英文大小写，不猜测或模糊合并不同名称。

建议项目提供稳定的网站名称，避免登录页和首页使用不同的标题：

```html
<meta name="application-name" content="项目 A">
```

在桌面端添加或编辑开发网站时，可填写「项目名称」。它需要与网页上识别出的项目名称一致；「名称」仍可作为自定义展示标签，用来区分同名账号。

同地址、同项目名称匹配到多条记录时，LocalPass 显示独立的账号选择窗口，包含项目名称、用户名、展示标签和记录编号。即使主窗口隐藏在托盘中，该窗口也会显示。选择后只填充这一条，取消、关闭窗口、超时或锁定密码库均不填充。

保存登录时，如果同项目、同用户名已有记录且密码不同，会询问更新对象，也可以「另存为新记录」。通过扩展明确选择的记录，在五分钟内的同页面登录中可直接更新对应记录；选择不会跨密码库、地址、项目或用户名生效。

没有项目名称的旧扩展请求和没有可用名称的旧记录需要手动选择。网页明确提供了不同项目名称时，不会自动回退到其他已命名项目。原有数据库会增加项目字段，原密码和版本历史保留；加密备份保留项目字段与同名独立记录。

后台保存和弹窗需要桌面端仍在运行且密码库已解锁。完全退出应用后，扩展无法保存、填充或显示桌面选择窗口。

验证命令：`npm test`、`npm run test:site-data`、`npm run test:extension`、`npm run test:projects`、`npm run test:startup`。
